# 提示词工程基础

提示词工程（Prompt Engineering）是与大语言模型交互的核心技能。它并不是简单的"提问技巧"，而是**面向概率性模型的接口编程**。

## 为什么提示词如此重要

大语言模型基于自回归机制工作：给定前文（Prompt），模型预测下一个 Token 的概率分布。这意味着：

- 提示词的**每一个字**都会影响输出的概率分布
- 好的提示词能显著约束模型的输出空间，减少幻觉
- 差的提示词会让模型"自由发挥"，产生不可预测的结果

## 提示词的基本构成要素

一个结构完整的提示词通常包含以下四个部分：

| 要素 | 作用 | 示例 |
| :--- | :--- | :--- |
| **角色设定** | 激活模型特定领域的知识分布 | "你是一名资深前端架构师" |
| **任务描述** | 明确说明要模型做什么 | "请审查以下代码的性能问题" |
| **上下文信息** | 提供完成任务所需的背景材料 | 代码片段、文档、数据 |
| **输出约束** | 规定输出的格式与边界 | "以 JSON 格式输出，包含 issue 和 fix 字段" |

## 第一个结构化提示词

```text
你是一名资深的 JavaScript 代码审查专家。

请审查下面的代码，找出其中的问题：

function getUser(id) {
  return fetch('/api/users/' + id)
    .then(res => res.json())
}

要求：
1. 逐条列出问题，说明原因
2. 给出修改后的完整代码
3. 如果没有发现问题，输出"未发现问题"
```

这个提示词包含了角色、任务、上下文和输出约束，模型的输出会比"帮我看看这段代码"稳定得多。

## 关键原则

> **核心心法**：把模型当成一位知识渊博但需要清晰指令的新同事。你给的指令越具体、越结构化，它的产出就越可靠。

1. **具体优于抽象**："列出 3 个性能问题" 优于 "分析一下性能"
2. **示例优于描述**：给出期望输出的样例（Few-shot），比冗长的文字描述更有效
3. **约束输出格式**：要求 JSON、Markdown 表格等结构化格式，方便下游程序解析
4. **设置兜底行为**：明确告诉模型"如果信息不足，输出 INSUFFICIENT_DATA"，避免它凭空编造
